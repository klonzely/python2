# Лабораторная работа №4 — Интерфейсы и абстрактные классы (ABC)

## Цель работы

- Познакомиться с абстрактными базовыми классами (ABC) в Python.
- Освоить понятие интерфейса как контракта поведения.
- Научиться задавать обязательные для реализации методы.
- Закрепить полиморфизм через единый интерфейс.
- Интегрировать интерфейсы с коллекциями (фильтрация, сортировка).

## Описание интерфейсов

Созданы два абстрактных класса (интерфейса) в модуле `interfaces.py`:

| Интерфейс      | Абстрактный метод | Назначение |
|----------------|-------------------|-------------|
| `Attackable`   | `attack() -> float` | Вычисление урона при атаке |
| `Displayable`  | `display_info() -> str` | Получение строкового представления объекта для вывода |

Оба интерфейса наследуются от `ABC` и используют декоратор `@abstractmethod`.

## Реализация в классах

### Базовый абстрактный класс `Weapon`

- Расположен в `models.py`.
- Реализует оба интерфейса (`Attackable`, `Displayable`), но оставляет методы `attack()` и `display_info()` абстрактными.
- Содержит общую логику: валидацию, свойства (`name`, `damage`, `rarity`, `level`, `is_broken`), методы `upgrade()`, `repair()`, `break_weapon()`.
- Использует модуль `validate.py` для проверки входных данных.

### Конкретные классы-наследники

#### `MeleeWeapon` (ближний бой)
- Добавляет атрибут `sharpness` (острота).
- Реализует `attack()` с учётом уровня, редкости и остроты. Если сломано → 0 урона.
- Реализует `display_info()` с эмодзи 🔪, показывая итоговый урон.

#### `RangedWeapon` (дальний бой)
- Добавляет атрибут `ammo` (количество боеприпасов).
- Реализует `attack()`: расходует 1 патрон, при отсутствии патронов или поломке урон = 0.
- Реализует `display_info()` с эмодзи 🏹 и отображает число патронов.

**Разное поведение методов интерфейса**:
- Урон ближнего оружия зависит от `sharpness` и не расходует ресурсы.
- Урон дальнего оружия расходует боеприпасы и может стать нулевым при их отсутствии.
- Отображение информации различается иконками и набором полей.

### Сценарий 1: Создание объектов и вызов `display_info()`
Создаются экземпляры `MeleeWeapon` и `RangedWeapon`, выводится их информация через метод интерфейса `Displayable`.

### Сценарий 2: Универсальная функция `print_attack_damage`
Функция принимает любой объект, реализующий интерфейс `Attackable`, и печатает его урон. Демонстрация полиморфизма.

### Сценарий 3: Работа с коллекцией `WeaponInventory`
- Добавление оружия в коллекцию.
- Фильтрация объектов по интерфейсу (`filter_by_interface(Displayable)`).
- Сортировка по урону через интерфейс `Attackable` (`sort_by_attack`).

### Сценарий 4: Проверка множественной реализации интерфейсов
Используется `isinstance(obj, Attackable)` и `isinstance(obj, Displayable)`. Оба класса-наследника проходят проверку на оба интерфейса.

### Сценарий 5: Обработка ошибок
Попытка создать оружие с пустым именем, отрицательным уроном или недопустимой редкостью – выбрасываются исключения (унаследовано от ЛР-3).
