# Лабораторная работа №6 — Аннотации типов, Generic-классы и Protocol

## Цель работы

- Освоить систему аннотаций типов в Python (модуль `typing`).
- Научиться создавать обобщённые (generic) классы с помощью `TypeVar` и `Generic`.
- Понять концепцию структурной типизации через `typing.Protocol`.

## Описание реализованных типов и контейнеров

### Generic-класс `TypedCollection[T]`

- Полностью типизированная коллекция, аналогичная по интерфейсу коллекции из ЛР-2.
- Параметр типа `T` означает, какой тип объектов хранится внутри.
- Методы:
  - `add(item: T) -> None`
  - `remove(item: T) -> None`
  - `get_all() -> list[T]`
  - `find(predicate: Callable[[T], bool]) -> Optional[T]`
  - `filter(predicate: Callable[[T], bool]) -> list[T]`
  - `map(transform: Callable[[T], R]) -> list[R]`   (R – второй `TypeVar`)

### Протоколы (задание на 5)

- `Displayable(Protocol)` – требует наличия метода `display()` -> `str`.
- `Scorable(Protocol)` – требует наличия метода `score()` -> `float`.

Классы `MeleeWeapon` и `RangedWeapon` **не наследуются** от этих протоколов, но содержат методы `display()` и `score()` – поэтому они автоматически соответствуют протоколам (структурная типизация).

### TypeVar с ограничением (bound)

- `D = TypeVar('D', bound=Displayable)` – может быть только объект, реализующий `Displayable`.
- `S = TypeVar('S', bound=Scorable)` – аналогично для `Scorable`.

Благодаря этому `TypedCollection[D]` может вызывать `item.display()` у каждого элемента, зная, что метод существует.

## Вывод

В ходе лабораторной работы изучены и применены:

- **Аннотации типов** – улучшают читаемость и помогают инструментам (IDE, mypy) находить ошибки.
- **Generic`и (`TypeVar`, `Generic`)** – позволяют создавать переиспользуемые контейнеры, сохраняющие информацию о типе элементов.
- **`Protocol` (структурная типизация)** – вместо явного наследования объект подходит протоколу, если имеет нужные методы («утиная типизация» на уровне статического анализа).
- **Ограничения `bound`** – гарантируют, что внутрь коллекции можно положить только объекты, поддерживающие определённый интерфейс.

Такой подход делает код более надёжным, самодокументированным и удобным для сопровождения.
